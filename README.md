# 假期安排 uTools 插件

用于按大小休周期计算月度休息日，并从官方安排中筛出真正增加的放假天数。

- 日历可切换每周从星期几开始，默认周日。
- 日历按上午、下午分别显示状态；两个时段相同时合并为全天。
- 放假、法定调休和法定补班作为日期标签；其中纯假期会参与实际休息结果，两个调班标签不参与。
- 右侧放假明细只列出日期，不标注上午、下午或全天；调休与补班记录显示在日历下方。
- 周六、周日可分别配置休息时段与重复间隔，默认使用大小休预设。
- 重复间隔 `0` 表示每周应用，`1` 表示隔 1 周应用一次；未轮到应用的周按上班处理。
- 双休、单休、大小休都是周六和周日规则的快捷预设，可继续手动调整。

## 计算口径

- `放假`：纯假期只按整天分配，不拆分为两个半天；优先取假期区间内原本全天上班的日期。
- `法定调休`：全天官方调休推荐显示日期标签，但不改变实际结果；只有一个工作半天被推荐调休时不显示标签，该半天未人工调休仍正常显示上班。
- `休息日重合`：完全按照大小休配置显示普通休息，不额外标记节日或重合状态。
- `法定补班`：只作为官方安排标签，不会直接记为实际补班。

右键点击日历日期可打开调班与修正窗口；同日有多项时继续使用列表选择，编辑窗口在“调班 / 修正”标签间切换。一次调班操作可以添加多段调休或补班日期（精确到上午、下午），关联类型可选“需要”或“不需要”；选择“需要”时允许暂时只填一类日期。编辑中选到已有调班的有效半天会并入当前操作，原操作未被选中的时段自动拆分保留。记录列表继续分别显示调休和补班，但编辑、删除针对整次操作。旧版本本地数据不做迁移，载入新版本时自动清理旧存储；旧版导出 JSON 拒绝导入。一次操作中的所有日期都早于系统当天时，会在加载、导入或再次进入插件时清理整次操作；含今天或未来日期的操作整体保留。调休和补班记录以 `0.5` 天为最小单位。实际结果先按周末配置和官方纯假期计算；人工调休只累计仍为上班的时段，人工补班只累计已经休息的时段。人工记录会覆盖日历对应的上午或下午，最终显示为上班、休息、调休或补班。只有关联类型为“需要”的操作参与余额互抵；选择“不需要”仍改变日历状态并显示记录，但不计入余额。负数余额显示为 `0`。

内置数据为 2026 年国务院办公厅公布的放假调休安排；法定日期按现行《全国年节及纪念日放假办法》拆分。进入本地尚无数据的年份时，插件会从 `NateScarlet/holiday-cn` 自动获取并保存；获取失败不会覆盖已有数据。其他年份也可在日历中逐日维护，或通过 JSON 导入。

## 本地运行

浏览器预览时，在当前目录启动任意静态服务器：

```bash
python3 -m http.server 4173
```

## uTools 载入

1. 打开 uTools 开发者工具。
2. 新建项目并选择本目录的 `plugin.json`。
3. 进入“假期安排”功能。

设置与节假日数据优先保存在 `utools.dbStorage`，普通浏览器预览时回退到 `localStorage`。首次获取新年份数据时需要联网。

数据保存和 JSON 导出使用同一种结构：节假日区间只保存一份元数据，零散日期保存在 `holidayData.days`；若区间中的某天被修正或删除，会用区间的 `dates` 列表保留其余日期。加载时恢复为按日期索引的日历数据。当前格式不兼容旧版存储或导出文件；启动新版本时旧版存储键会清理，旧版文件不能导入。

## 导入节假日数据

设置中的“节假日数据 > 导入”接受与“导出”一致的完整 JSON 文件，页面中的“节假日数据 JSON 结构”可展开查看可导入的示例。必须包含当前 `version: 7` 和 `holidayData: { blocks: [], days: {} }`；`blocks` 保存节假日区间（可选 `dates` 指定尚保留的日期），`days` 保存零散日期修正。`settings` 配置周末规则，`adjustments` 以一次操作及多段上午/下午范围保存调班，`associationType` 为 `required` 或 `none`。导入会覆盖当前全部数据；旧版文件不支持，全部调班日期均早于系统当天的操作会在导入时清理。

## 配色方案

外观设置的“明暗模式”控制跟随系统、浅色或深色；“配色方案”可选择默认配色、内置配色名称或自定义。内置方案来自项目 `themes/` 的 JSON 文件，每份必须有 `name`、完整的 `light` 和 `dark` 配置。浏览器预览从 `themes/index.json` 清单读取，uTools 从预加载脚本读取目录；离线构建包含整个目录。选择内置配色不会清除已保存的自定义值；导入或修改配色会切换到“自定义”，随时可以切回内置配色。

## 导入配色方案

外观设置中的“导入配色”接受独立 JSON 配色方案，也接受“导出数据”生成的完整 JSON（读取其中的 `customColors`，不修改其他设置）。独立方案结构如下：

```json
{
  "light": { "page": "#eef0ed", "stripe": "#26756824" },
  "dark": { "page": "#141a16", "stripe": "#75d0b130" }
}
```

`light`、`dark` 都必须是对象，可以只列出需要自定义的字段；导入会替换浅深两套自定义配色，未列出的字段恢复默认，两个对象都为空则恢复两套默认。普通字段使用 `#RRGGBB`，`toc-bg`、`stripe`、`tag-neutral-bg` 使用 `#RRGGBBAA`（末尾 `AA` 为透明度，`00` 全透明、`ff` 完全不透明）。已知字段的错误颜色会拒绝整份文件。

可用字段：

- 页面与文字：`page, surface, panel, panel-muted, header, header-text, header-muted, text, muted, faint, toc-bg`
- 控件与边框：`border, border-strong, control, hover, warm-hover, badge-bg, primary, primary-hover, primary-text, error-strong`
- 日历与状态：`rest-bg, holiday-bg, manual-rest-bg, manual-work-bg, green, red, purple, gold, stripe`
- 标签与提示：`tag-work-bg, tag-suggestion-bg, tag-holiday-bg, preview-bg, preview-error-bg, tag-neutral-bg`

## 构建离线安装包

不要直接选择包含 `.git` 的项目根目录。先生成干净的打包目录：

```bash
npm run build:offline
```

然后在 uTools 开发者工具中选择 `dist/holiday-planner-utools` 目录构建离线安装包。该目录只包含插件运行所需文件，不包含 Git、测试或开发配置。

如果在 Windows 版 uTools 中开发 WSL 项目，不要直接选择 `\\wsl.localhost\...` 目录打包。请先把上述目录复制到 Windows 本机路径，再从本机目录重新载入 `plugin.json` 并构建离线安装包，避免打包器漏掉运行文件。
